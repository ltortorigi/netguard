NETGUARD — UNA SYSTEMS
Logan Tortorigi

WHAT IT DOES
NetGuard helps UNA students see whether campus service entry points respond,
report problems, and check official provider status pages. It is an independent
student project, not UNA's official status service.

HOW TO RUN ON WINDOWS
1. Open PowerShell in the netguard folder containing package.json.
2. Run: npm.cmd ci
3. If .env does not exist, run: Copy-Item .env.example .env
4. Run: notepad .env
5. Set your own unique ADMIN_PASSWORD with at least 12 characters. Keep it private.
6. Run: npm.cmd start
7. Open http://127.0.0.1:3000/ for the public UNA dashboard.

WHAT TO SHOW
- UNA website, Canvas, and UNAPortal cards with automated entry-point checks.
- Email and campus Wi-Fi cards, which use community reports only.
- A card's History button and saved timestamps/results.
- On a LOCAL DEMO ONLY, submit a report, show the count/chart, then try another
  report for the same system to show duplicate protection. Explain that this
  is test data; do not submit a fake problem to a public production dashboard.
- The Down Detector chart, official status links, and external Downdetector link.
- Explain that NetGuard's reports are its own data, not imported from Downdetector.

WHAT TO EXPLAIN
Node.js/Express runs the app. Three fixed public HTTPS entry points are checked
every five minutes. A five-second deadline prevents stuck checks. Results and
reports persist in MongoDB when configured, or in a local JSON file for demos.

A responding login page does not prove an entire system works. A failed check
might be a monitor/network issue. Reports are unverified. No UNA passwords are
collected. Shared campus networks can undercount reports because the duplicate
limit uses a keyed network-address hash per system and 15-minute window.

ORIGINAL TCP OUTAGE/RECOVERY DEMO
Open http://127.0.0.1:3000/admin and sign in with your private admin password.
In a second PowerShell window in the same folder, run:
npm.cmd run demo:walkthrough
Refresh the ADMIN dashboard after each prompt. It will show reachable,
unreachable, then reachable again. Only the disposable localhost service is
stopped. Do not run demo:target at the same time.
